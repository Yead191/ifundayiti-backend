================================================================================
COMPLETE SPECIFICATION & PROMPT: FOLDER-BASED GALLERY SYSTEM
(FOR WEBSITE & ADMIN DASHBOARD)
================================================================================

Target Applications:
  1. User Website (Public Gallery: Folder Browser & Image Lightbox View)
  2. Admin Dashboard (Admin Portal: Folder Management & Gallery Image Management)
Base API Routes:
  - Folders: /folder (or /api/v1/folder)
  - Gallery: /gallery (or /api/v1/gallery)
Authentication:
  - Folder & Gallery Creation / Modification / Deletion: Bearer Token (ADMIN, SUPER_ADMIN)
  - Public Viewing: Public (GET /folder, GET /folder/:id, GET /gallery)

================================================================================
1. ARCHITECTURAL & USER WORKFLOW
================================================================================

A. NAVIGATION HIERARCHY (FOLDER-FIRST WORKFLOW):
   1. User / Admin enters the Gallery section (/gallery or /admin/gallery).
   2. The initial view is the FOLDERS DIRECTORY:
      - Displays all folders as visual folder cards/tiles.
      - Each card shows: Folder Name, Image Count (galleryCount), Creation Date.
      - Search bar allows quick searching of folders by name.
      - Admin has "Create New Folder", "Edit Folder Name", and "Delete Folder" actions.
   3. Clicking any Folder card navigates into that Folder's Gallery View:
      - Route URL: /gallery/folder/[folderId] (or /gallery?folder=[folderId])
      - Top Bar / Header displays a Breadcrumb:
        "Gallery  >  [Folder Name]" with a "Back to Folders" button.
      - Displays all gallery photos/items assigned to this folder.
      - In Admin Dashboard, an "Add Image to this Folder" button is prominent.

B. ADDING IMAGES TO FOLDERS:
   - Admin opens a folder and clicks "Add Image" (or selects the folder from a dropdown in the upload modal).
   - Frontend calls `POST /gallery` with `multipart/form-data`, passing:
     - `image` (File)
     - `folder` (Selected Folder ID)
     - `title` (Required string)
     - `category`, `location`, `date`, `status` (Draft | Published | Archived), `featured` (boolean)
   - Backend links the uploaded image directly to that folder.

C. CASCADING FOLDER DELETION:
   - When Admin deletes a folder (`DELETE /folder/:id`):
     1. The backend finds all gallery images assigned to this folder.
     2. Calls `unlinkFile(gallery.image)` on disk to safely purge physical files.
     3. Deletes all associated gallery records from the database.
     4. Deletes the folder document.
   - Confirmation Modal in UI:
     "Are you sure you want to delete this folder? All [X] images inside this folder will be permanently deleted from the system and storage."

D. EXISTING GALLERY FUNCTIONALITIES PRESERVED:
   - Category filtering (Community Outreach, Events, Healthcare, Education, etc.).
   - Status toggle (Draft, Published, Archived).
   - Featured toggle (Pin items to featured sections).
   - Search by title, description, category, and location.
   - Image preview / lightbox modal.
   - Individual image edit & individual image delete.

2. TYPESCRIPT DATA INTERFACES
================================================================================

```typescript
// Folder Interface (Lightweight, name-only)
export interface IFolder {
  _id: string;
  name: string;
  galleryCount?: number;
  createdAt: string;
  updatedAt: string;
}

// Gallery Status Enum
export enum GALLERY_STATUS {
  DRAFT = 'Draft',
  PUBLISHED = 'Published',
  ARCHIVED = 'Archived',
}

// Gallery Item Interface
export interface IGallery {
  _id: string;
  title: string;
  description?: string;
  image: string;
  folder?: {
    _id: string;
    name: string;
  } | string;
  category?: string;
  location?: string;
  date?: string;
  status: GALLERY_STATUS;
  featured: boolean;
  createdAt: string;
  updatedAt: string;
}
```

3. API ENDPOINTS SPECIFICATION
================================================================================

--------------------------------------------------------------------------------
A. FOLDER ENDPOINTS (/folder)
--------------------------------------------------------------------------------

1) GET ALL FOLDERS
   - Method: GET /folder
   - Access: Public
   - Query Params:
     - `page`: number (default: 1)
     - `limit`: number (default: 20)
     - `searchTerm`: string (searches folder `name`)
     - `sort`: string (default: "-createdAt")
   - Response (200 OK):
     {
       "statusCode": 200,
       "success": true,
       "message": "Folders fetched successfully",
       "data": [
         {
           "_id": "67cb1a2b3c4d5e6f7a8b9c01",
           "name": "Haiti Community Outreach 2026",
           "galleryCount": 14,
           "createdAt": "2026-09-10T10:00:00.000Z",
           "updatedAt": "2026-09-10T10:00:00.000Z"
         }
       ],
       "pagination": { "page": 1, "limit": 20, "total": 1, "totalPage": 1 }
     }

2) GET SINGLE FOLDER
   - Method: GET /folder/:id
   - Access: Public
   - Response (200 OK):
     {
       "statusCode": 200,
       "success": true,
       "message": "Folder fetched successfully",
       "data": {
         "_id": "67cb1a2b3c4d5e6f7a8b9c01",
         "name": "Haiti Community Outreach 2026",
         "galleryCount": 14,
         "createdAt": "2026-09-10T10:00:00.000Z"
       }
     }

3) CREATE FOLDER
   - Method: POST /folder
   - Access: ADMIN, SUPER_ADMIN
   - Headers: { "Authorization": "Bearer <token>", "Content-Type": "application/json" }
   - Request Body:
     {
       "name": "Summer Grant Projects"
     }
   - Validation: `name` is required, trimmed, unique.
   - Response (201 Created):
     {
       "statusCode": 201,
       "success": true,
       "message": "Folder created successfully",
       "data": { ...folderObject }
     }

4) UPDATE FOLDER
   - Method: PATCH /folder/:id
   - Access: ADMIN, SUPER_ADMIN
   - Request Body:
     {
       "name": "Updated Folder Name"
     }
   - Response (200 OK):
     {
       "statusCode": 200,
       "success": true,
       "message": "Folder updated successfully",
       "data": { ...folderObject }
     }

5) DELETE FOLDER (CASCADE DELETE)
   - Method: DELETE /folder/:id
   - Access: ADMIN, SUPER_ADMIN
   - Behavior:
     * Automatically finds all images linked to this folder.
     * Deletes every physical image file from storage via `unlinkFile`.
     * Deletes all linked gallery items from the database.
     * Deletes the folder itself.
   - Response (200 OK):
     {
       "statusCode": 200,
       "success": true,
       "message": "Folder deleted successfully",
       "data": { ...deletedFolderObject }
     }

--------------------------------------------------------------------------------
B. GALLERY ENDPOINTS (/gallery)
--------------------------------------------------------------------------------

1) GET GALLERIES BY FOLDER (OR ALL)
   - Method: GET /gallery
   - Access: Public (Public sees 'Published'; Admin sees all statuses)
   - Query Params:
     - `folder`: string (Folder ID to view images inside that folder)
     - `category`: string (Filter by category)
     - `status`: "Draft" | "Published" | "Archived" (Admin only)
     - `featured`: boolean
     - `searchTerm`: string (searches title, description, category, location)
     - `page`: number
     - `limit`: number
   - Response (200 OK):
     {
       "statusCode": 200,
       "success": true,
       "message": "Galleries fetched successfully",
       "data": [
         {
           "_id": "67cb2b...",
           "title": "Medical Supplies Delivery",
           "image": "image/image-17890123.jpg",
           "folder": {
             "_id": "67cb1a...",
             "name": "Haiti Community Outreach 2026"
           },
           "category": "Healthcare",
           "location": "Cap-Haïtien",
           "status": "Published",
           "featured": true,
           "createdAt": "2026-09-10T10:15:00.000Z"
         }
       ],
       "pagination": { ... }
     }

2) CREATE GALLERY IMAGE
   - Method: POST /gallery
   - Access: ADMIN, SUPER_ADMIN
   - Content-Type: multipart/form-data
   - Form Data Fields:
     - `image`: File (Required)
     - `folder`: string (Folder ID) [Required in folder workflow]
     - `title`: string (Required)
     - `category`: string (Required)
     - `description`: string (Optional)
     - `location`: string (Optional)
     - `date`: string (Optional)
     - `status`: "Draft" | "Published" | "Archived" (Optional, default: Draft)
     - `featured`: boolean (Optional, default: false)
   - Response (201 Created):
     {
       "statusCode": 201,
       "success": true,
       "message": "Gallery item created successfully",
       "data": { ...galleryObject }
     }

3) UPDATE GALLERY IMAGE
   - Method: PATCH /gallery/:id
   - Access: ADMIN, SUPER_ADMIN
   - Content-Type: multipart/form-data
   - Form Data: Any updated fields (title, category, folder, image, etc.)

4) DELETE SINGLE GALLERY IMAGE
   - Method: DELETE /gallery/:id
   - Access: ADMIN, SUPER_ADMIN
   - Behavior: Unlinks physical image and deletes database entry.

5) UPDATE STATUS & TOGGLE FEATURED
   - PATCH /gallery/status/:id -> `{ "status": "Published" | "Draft" | "Archived" }`
   - PATCH /gallery/featured/:id -> Toggles boolean `featured` flag

6) GET STATS
   - GET /gallery/stats -> Returns counts for published, draft, archived, featured.
