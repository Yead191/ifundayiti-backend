================================================================================
COMPLETE SPECIFICATION & PROMPT: FOLDER-BASED ALBUM & GALLERY SYSTEM
(UPDATED: FOLDER HOLDS ALL METADATA, GALLERY CONTAINS IMAGES ONLY)
================================================================================

Target Applications:
  1. User Website (Public Gallery: Album/Folder Directory & Photo Grid / Lightbox)
  2. Admin Dashboard (Admin Portal: Folder Management with Full Metadata & Batch Photo Uploader)
Base API Routes:
  - Folders: /folder (or /api/v1/folder)
  - Gallery: /gallery (or /api/v1/gallery)
Authentication:
  - Creation / Modification / Deletion / Admin Views: Bearer Token (ADMIN, SUPER_ADMIN)
  - Public Viewing: Public (GET /folder, GET /folder/:id, GET /gallery)

================================================================================
1. ARCHITECTURAL OVERVIEW & ROLES
================================================================================

A. FOLDER (ALBUM / EVENT / STORY):
   The Folder is now the central entity that carries ALL information and metadata:
   - `name`: string (required, unique)
   - `description`: string (optional detailed narrative/story)
   - `image`: string (optional cover photo for the folder/album)
   - `category`: string (Community Outreach, Grant Programs, Education, Healthcare, Events, etc.)
   - `location`: string (e.g., Port-au-Prince, Cap-Haïtien)
   - `date`: string/Date (e.g. event date or album creation date)
   - `status`: "Draft" | "Published" | "Archived" (default: Published)
   - `featured`: boolean (pinned to home page / featured gallery carousel)
   - `galleryCount`: number (automatically computed count of images inside this folder)

B. GALLERY (PHOTOS ONLY):
   The Gallery items represent strictly individual photos belonging to a folder:
   - `folder`: ObjectId (Folder ID reference, required)
   - `image`: string (file path on disk, e.g. /image/photo-17890123.jpg, required)
   - `caption`: string (optional short image caption/label)
   - Supports uploading single or multiple images at once (up to 20 images in a single request).

C. CASCADE DELETION & STORAGE CLEANUP:
   When an admin deletes a folder (`DELETE /folder/:id`):
   - The backend deletes the folder's cover image file from disk via `unlinkFile`.
   - The backend finds all associated images in `Gallery` for that folder.
   - For every associated image, it unlinks the physical file from disk via `unlinkFile`.
   - Deletes all assigned `Gallery` database records.
   - Deletes the `Folder` database record.
   - When deleting an individual gallery photo (`DELETE /gallery/:id` or `DELETE /gallery/delete-multiple`), the backend unlinks each image file from disk and deletes the record.

2. TYPESCRIPT DATA INTERFACES

```typescript
// Folder Status Enum
export enum FOLDER_STATUS {
  DRAFT = 'Draft',
  PUBLISHED = 'Published',
  ARCHIVED = 'Archived',
}

// Folder Categories (Preset list)
export const FOLDER_CATEGORIES = [
  'Community Outreach',
  'Grant Programs',
  'Education',
  'Food & Agriculture',
  'Healthcare',
  'Community Development',
  'Entrepreneurship',
  'Environment',
  'Events',
  'Volunteering',
  'Success Stories',
  'Other',
] as const;

// Folder (Album) Interface - Contains all story & event metadata
export interface IFolder {
  _id: string;
  name: string;
  description?: string;
  image?: string; // Cover photo
  category?: string;
  location?: string;
  date?: string | Date;
  status: FOLDER_STATUS;
  featured: boolean;
  galleryCount?: number; // Calculated dynamically by backend
  createdAt: string;
  updatedAt: string;
}

// Gallery Photo Item Interface - Strictly photo + folder ref + caption
export interface IGallery {
  _id: string;
  folder: string | {
    _id: string;
    name: string;
    image?: string;
    category?: string;
    location?: string;
    date?: string;
    status?: FOLDER_STATUS;
    featured?: boolean;
  };
  image: string; // File URL/path
  caption?: string; // Optional short caption
  createdAt: string;
  updatedAt: string;
}

// Folder Stats Response Interface
export interface IFolderStats {
  totalFolders: number;
  publishedFolders: number;
  draftFolders: number;
  archivedFolders: number;
  featuredFolders: number;
  totalImages: number;
}
```

3. API ENDPOINTS SPECIFICATION
================================================================================

--------------------------------------------------------------------------------
A. FOLDER ENDPOINTS (/folder)
--------------------------------------------------------------------------------

1) GET ALL FOLDERS
   - Method: GET /folder
   - Access: Public (Guests receive Published folders; Admins with Bearer token receive all folders)
   - Query Parameters:
     - `page`: number (default: 1)
     - `limit`: number (default: 10)
     - `searchTerm`: string (searches `name`, `description`, `category`, `location`)
     - `category`: string (filter by category)
     - `status`: "Draft" | "Published" | "Archived"
     - `featured`: boolean
     - `sort`: string (default: "-featured -createdAt")
   - Response (200 OK):
     {
       "statusCode": 200,
       "success": true,
       "message": "Folders fetched successfully",
       "pagination": { "page": 1, "limit": 10, "total": 3, "totalPage": 1 },
       "data": [
         {
           "_id": "67cb1a2b3c4d5e6f7a8b9c01",
           "name": "Cap-Haïtien Community Clinic 2026",
           "description": "Providing mobile clinic health screenings and medical kits.",
           "image": "/image/clinic-cover-17890123.jpg",
           "category": "Healthcare",
           "location": "Cap-Haïtien",
           "date": "2026-08-15T00:00:00.000Z",
           "status": "Published",
           "featured": true,
           "galleryCount": 24,
           "createdAt": "2026-08-16T10:00:00.000Z",
           "updatedAt": "2026-08-16T10:00:00.000Z"
         }
       ]
     }

2) GET SINGLE FOLDER
   - Method: GET /folder/:id
   - Access: Public
   - Response (200 OK): Returns folder details with `galleryCount`.

3) CREATE FOLDER (WITH COVER PHOTO & METADATA)
   - Method: POST /folder
   - Access: ADMIN, SUPER_ADMIN
   - Headers: `Authorization: Bearer <token>`
   - Content-Type: `multipart/form-data`
   - Form Fields:
     - `name`: string (Required, unique)
     - `description`: string (Optional)
     - `category`: string (Optional)
     - `location`: string (Optional)
     - `date`: string (ISO date string, optional)
     - `status`: "Draft" | "Published" | "Archived" (Optional, default: Published)
     - `featured`: boolean (Optional, default: false)
     - `image`: File (Cover image file, optional)
   - Response (201 Created): Returns created folder object.

4) UPDATE FOLDER
   - Method: PATCH /folder/:id
   - Access: ADMIN, SUPER_ADMIN
   - Content-Type: `multipart/form-data`
   - Form Fields: Any updated metadata fields or a new `image` file (old image will be automatically unlinked if replaced).
   - Response (200 OK): Returns updated folder object.

5) UPDATE FOLDER STATUS
   - Method: PATCH /folder/status/:id
   - Access: ADMIN, SUPER_ADMIN
   - Request Body: `{ "status": "Published" }` ("Draft" | "Published" | "Archived")
   - Response (200 OK)

6) TOGGLE FOLDER FEATURED
   - Method: PATCH /folder/featured/:id
   - Access: ADMIN, SUPER_ADMIN
   - Request Body: `{}` (toggles `featured` boolean)
   - Response (200 OK)

7) GET FOLDER & GALLERY STATS
   - Method: GET /folder/stats
   - Access: ADMIN, SUPER_ADMIN
   - Response (200 OK):
     {
       "statusCode": 200,
       "success": true,
       "message": "Folder stats fetched successfully",
       "data": {
         "totalFolders": 12,
         "publishedFolders": 10,
         "draftFolders": 1,
         "archivedFolders": 1,
         "featuredFolders": 3,
         "totalImages": 142
       }
     }

8) DELETE FOLDER (FULL CASCADE CLEANUP)
   - Method: DELETE /folder/:id
   - Access: ADMIN, SUPER_ADMIN
   - Automatically unlinks folder cover photo + all gallery image files for this folder, and deletes all DB records.
   - Response (200 OK)

--------------------------------------------------------------------------------
B. GALLERY ENDPOINTS (/gallery - IMAGES ONLY)
--------------------------------------------------------------------------------

1) GET ALL IMAGES IN A FOLDER (OR ALL IMAGES)
   - Method: GET /gallery
   - Access: Public
   - Query Parameters:
     - `folder`: string (Folder ObjectId - filter photos belonging to this folder)
     - `page`: number (default: 1)
     - `limit`: number (default: 20)
     - `sort`: string (default: "-createdAt")
     - `searchTerm`: string (searches `caption`)
   - Response (200 OK):
     {
       "statusCode": 200,
       "success": true,
       "message": "Galleries fetched successfully",
       "pagination": { "page": 1, "limit": 20, "total": 24, "totalPage": 2 },
       "data": [
         {
           "_id": "67cb2b...",
           "folder": {
             "_id": "67cb1a...",
             "name": "Cap-Haïtien Community Clinic 2026"
           },
           "image": "/image/photo-17890456.jpg",
           "caption": "Doctors preparing free health screening kits",
           "createdAt": "2026-08-16T11:00:00.000Z"
         }
       ]
     }

2) ADD IMAGE(S) TO A FOLDER (SUPPORTS BATCH UPLOADS)
   - Method: POST /gallery
   - Access: ADMIN, SUPER_ADMIN
   - Content-Type: `multipart/form-data`
   - Form Fields:
     - `folder`: string (Folder ID, required)
     - `caption`: string (Optional short caption)
     - `image`: File OR Multiple Files (supports up to 20 images at once under field name `image`)
   - Response (201 Created):
     Returns single created object or array of created image objects.

3) GET SINGLE GALLERY IMAGE
   - Method: GET /gallery/:id
   - Access: Public
   - Response (200 OK)

4) UPDATE GALLERY IMAGE
   - Method: PATCH /gallery/:id
   - Access: ADMIN, SUPER_ADMIN
   - Content-Type: `multipart/form-data`
   - Form Fields: `caption`, `folder`, or new `image` File (replaces old file).
   - Response (200 OK)

5) DELETE SINGLE GALLERY IMAGE
   - Method: DELETE /gallery/:id
   - Access: ADMIN, SUPER_ADMIN
   - Unlinks image file from disk and deletes record.
   - Response (200 OK)

6) BATCH DELETE MULTIPLE GALLERY IMAGES
   - Method: DELETE /gallery/delete-multiple
   - Access: ADMIN, SUPER_ADMIN
   - Headers: `Content-Type: application/json`
   - Request Body:
     {
       "ids": ["67cb2b11...", "67cb2b22...", "67cb2b33..."]
     }
   - Unlinks all physical files from disk and deletes records.
   - Response (200 OK): `{ "statusCode": 200, "success": true, "message": "3 gallery image(s) deleted successfully" }`
