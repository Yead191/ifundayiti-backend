PART 3: BACKEND API REFERENCE CHEAT SHEET
--------------------------------------------------------------------------------

BASE URL:
  - http://localhost:5000/api/v1 (or your production base URL)
  - Folders: `/folder`
  - Gallery: `/gallery`

================================================================================
A. FOLDER ENDPOINTS (/folder)
================================================================================

1. GET ALL FOLDERS
   - Route: GET /folder
   - Auth: Optional (Public receives Published folders; Admins receive Draft/Published/Archived)
   - Query: `page`, `limit`, `searchTerm`, `category`, `status`, `featured`, `sort` (default: "-featured -createdAt")
   - Response: `{ statusCode: 200, success: true, data: [IFolder], pagination: {...} }`
   - Note: Each folder item automatically includes `galleryCount: number`.

2. GET SINGLE FOLDER
   - Route: GET /folder/:id
   - Auth: Public
   - Response: `{ statusCode: 200, success: true, data: IFolder }` (includes `galleryCount`)

3. CREATE FOLDER
   - Route: POST /folder
   - Auth: Bearer Token (ADMIN, SUPER_ADMIN)
   - Content-Type: multipart/form-data
   - Body Fields:
     - `name`: string (Required, unique)
     - `description`: string (Optional)
     - `category`: string (Optional)
     - `location`: string (Optional)
     - `date`: string (ISO date string, optional)
     - `status`: "Draft" | "Published" | "Archived" (Optional, default: "Published")
     - `featured`: boolean (Optional, default: false)
     - `image`: File (Cover image file, optional)

4. UPDATE FOLDER
   - Route: PATCH /folder/:id
   - Auth: Bearer Token (ADMIN, SUPER_ADMIN)
   - Content-Type: multipart/form-data
   - Body Fields: Any metadata fields above, or a new `image` cover file (automatically unlinks previous cover file).

5. UPDATE FOLDER STATUS
   - Route: PATCH /folder/status/:id
   - Auth: Bearer Token (ADMIN, SUPER_ADMIN)
   - Content-Type: application/json
   - Body: `{ "status": "Published" }` ("Draft" | "Published" | "Archived")

6. TOGGLE FOLDER FEATURED
   - Route: PATCH /folder/featured/:id
   - Auth: Bearer Token (ADMIN, SUPER_ADMIN)
   - Content-Type: application/json
   - Body: `{}` (toggles `featured` boolean flag)

7. GET FOLDER STATS
   - Route: GET /folder/stats
   - Auth: Bearer Token (ADMIN, SUPER_ADMIN)
   - Response:
     {
       "statusCode": 200,
       "success": true,
       "data": {
         "totalFolders": 12,
         "publishedFolders": 10,
         "draftFolders": 1,
         "archivedFolders": 1,
         "featuredFolders": 3,
         "totalImages": 142
       }
     }

8. DELETE FOLDER (CASCADE DELETE)
   - Route: DELETE /folder/:id
   - Auth: Bearer Token (ADMIN, SUPER_ADMIN)
   - Automatically unlinks folder cover photo + unlinks all gallery image files + deletes all gallery records + deletes folder.

================================================================================
B. GALLERY ENDPOINTS (/gallery - PHOTOS ONLY)
================================================================================

1. GET PHOTOS BY FOLDER (OR ALL)
   - Route: GET /gallery
   - Auth: Public
   - Query:
     - `folder`: string (Folder ID to filter photos inside an album)
     - `page`: number
     - `limit`: number
     - `sort`: string (default: "-createdAt")
     - `searchTerm`: string (searches `caption`)
   - Response: `{ statusCode: 200, success: true, data: [IGallery], pagination: {...} }`

2. ADD PHOTO(S) TO A FOLDER (BATCH OR SINGLE)
   - Route: POST /gallery
   - Auth: Bearer Token (ADMIN, SUPER_ADMIN)
   - Content-Type: multipart/form-data
   - Body Fields:
     - `folder`: string (Target Folder ID, Required)
     - `caption`: string (Optional note/caption)
     - `image`: File OR Multiple Files (supports up to 20 images at once!)
   - Response (201 Created): `{ statusCode: 201, success: true, message: "Gallery image(s) added successfully", data: [...] }`

3. GET SINGLE PHOTO
   - Route: GET /gallery/:id
   - Auth: Public

4. UPDATE PHOTO CAPTION / IMAGE / FOLDER
   - Route: PATCH /gallery/:id
   - Auth: Bearer Token (ADMIN, SUPER_ADMIN)
   - Content-Type: multipart/form-data (or application/json if not updating image file)
   - Body: `caption` (optional), `folder` (optional), `image` File (optional)

5. DELETE SINGLE PHOTO
   - Route: DELETE /gallery/:id
   - Auth: Bearer Token (ADMIN, SUPER_ADMIN)
   - Unlinks physical file and deletes DB record.

6. BATCH DELETE MULTIPLE PHOTOS
   - Route: DELETE /gallery/delete-multiple
   - Auth: Bearer Token (ADMIN, SUPER_ADMIN)
   - Content-Type: application/json
   - Body: `{ "ids": ["67cb...", "67cc..."] }`
   - Unlinks all physical files and deletes DB records.

C. TYPESCRIPT DATA MODELS
================================================================================

```typescript
export enum FOLDER_STATUS {
  DRAFT = 'Draft',
  PUBLISHED = 'Published',
  ARCHIVED = 'Archived',
}

export interface IFolder {
  _id: string;
  name: string;
  description?: string;
  image?: string;
  category?: string;
  location?: string;
  date?: string;
  status: FOLDER_STATUS;
  featured: boolean;
  galleryCount?: number;
  createdAt: string;
  updatedAt: string;
}

export interface IGallery {
  _id: string;
  folder: string | {
    _id: string;
    name: string;
    image?: string;
    category?: string;
    location?: string;
    date?: string;
    status?: FOLDER_STATUS;
    featured?: boolean;
  };
  image: string;
  caption?: string;
  createdAt: string;
  updatedAt: string;
}
```
