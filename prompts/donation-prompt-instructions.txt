FEATURE: Unified Multi-Source Fundraising (Offline Sales + E-Commerce Store Revenue)
PURPOSE & RATIONALE:
  Purchases from the iFundAyiti apparel/merchandise store constitute platform fundraising 
  alongside philanthropic donations. To give administrators and donors a single, cohesive, 
  and transparent view of platform health:
  1. E-Commerce Store Integration in Fund Stats (`GET /donation/fund-stats`):
     - `totalFundRaised` now automatically sums:
         (a) Offline manual fundraising records (`type: 'fund_raising'` from Donation DB)
         (b) PLUS Total revenue from paid store orders (`totalRevenue` from Order DB)
     - `fundRaisedCount` sums:
         (a) Offline fundraising transaction count
         (b) PLUS Number of completed paid store orders (`paidOrders` from Order DB)
  2. Updated Net Financial Formulas:
     - `totalInflows = totalDonations + totalFundRaised`
     - `totalBalance = totalInflows - totalGrants`
     - `totalCount = donationCount + grantCount + fundRaisedCount`
  3. Offline Merchandise & Direct Sales (`type: "fund_raising"`):
     - Added `DONATION_TYPE.FUND_RAISING` ('fund_raising').
     - Admins can log offline merchandise/ticket sales via `POST /donation/manual`
       with `type: "fund_raising"`, capturing `payment_method`, `reference`, and `notes`.
  4. Non-Blocking Concurrent Querying:
     - `getFundStatsFromDB` runs donation aggregation and store order analytics in
       parallel via `Promise.all` for sub-100ms response times.

--------------------------------------------------------------------------------
2. GET FUND STATISTICS (UNIFIED DONATIONS, STORE ORDERS & EXPENSES)
--------------------------------------------------------------------------------
- Method: GET /donation/fund-stats
- Access: ADMIN, SUPER_ADMIN
- Calculation Details:
  - `totalDonations`: Sum of all paid online and manual donations (`type: 'donation'`).
  - `totalFundRaised`: Sum of manual fundraising items (`type: 'fund_raising'`) + store orders revenue (`totalRevenue` from Order collection).
  - `donationCount`: Count of paid donation contributions.
  - `fundRaisedCount`: Count of manual fundraising entries + count of completed paid store orders (`paidOrders` from Order collection).
  - `totalGrants`: Total disbursed grants to winners.
  - `totalPaidExpenses`: Total operational expenses settled/paid (`payment_status === 'paid'`).
  - `paidExpenseCount`: Count of paid operational expense vouchers.
  - `totalBalance`: Net liquidity (`totalDonations + totalFundRaised - totalGrants - totalPaidExpenses`).
  - `totalCount`: `donationCount + grantCount + fundRaisedCount`.
  - `totalApplication`: Total application count.
- Response (200 OK):
  ```json
  {
    "statusCode": 200,
    "success": true,
    "message": "Fund stats fetched successfully",
    "data": {
      "totalBalance": 618.7,
      "totalDonations": 93,
      "totalGrants": 0,
      "totalFundRaised": 525.7,
      "totalPaidExpenses": 0,
      "donationCount": 6,
      "grantCount": 0,
      "fundRaisedCount": 10,
      "paidExpenseCount": 0,
      "totalCount": 16,
      "totalApplication": 3
    }
  }
  ```

--------------------------------------------------------------------------------

- Headers: `Content-Type: application/json`

  ```json
    "name": "John Doe",
    "email": "john@example.com",
    "amount": 50
  }
  ```
- Response (201 Created):
  ```json
  {

    "success": true,
    "message": "Donation checkout session created",
    "data": {
      "paymentUrl": "https://checkout.stripe.com/c/pay/cs_test_..."
    }
  }
  ```

--------------------------------------------------------------------------------
5. RECORD MANUAL / OFFLINE DONATION OR FUNDRAISING SALE (ADMIN)
--------------------------------------------------------------------------------
- Method: POST /donation/manual
- Access: ADMIN, SUPER_ADMIN
- Headers: `Authorization: Bearer <TOKEN>`, `Content-Type: application/json`
- Request Body (for Offline Fundraising / Merchandise):
  ```json
  {
    "name": "Walkathon T-Shirt Sales",
    "email": "supporter@example.com",
    "amount": 40,
    "type": "fund_raising",
    "payment_method": "cash",
    "reference": "BOOTH-TSHIRT-04",
    "notes": "Sold 2 iFundAyiti t-shirts at annual walkathon."
  }
  ```
- Request Body (for Direct Cash/Bank Donation):
  ```json
  {
    "name": "Jane Smith",
    "email": "jane@example.com",
    "amount": 250,
    "type": "donation",
    "payment_method": "bank_transfer",
    "reference": "WIRE-#9028",
    "notes": "Direct bank wire to platform endowment."
  }
  ```
- Supported `payment_method` values: `"cash"`, `"bank_transfer"`, `"direct"`, `"stripe"`, `"other"`
- Supported `type` values: `"donation"`, `"fund_raising"`
- Behavior:
  - Automatically sets `payment_status: "paid"`.
  - Sets `recordedBy` to the authenticated admin's ID.
  - Automatically increases `ProgramFund` balance.
  - Creates financial `Transaction` record for platform bookkeeping.
  - Sends receipt email to donor if email is provided.

--------------------------------------------------------------------------------
6. DELETE SINGLE DONATION RECORD
--------------------------------------------------------------------------------
- Method: DELETE /donation/:id
- Access: ADMIN, SUPER_ADMIN
- Response (200 OK):
  ```json

    "success": true,
    "message": "Donation record deleted successfully",
    "data": { ...deletedDonationObject }
  }
  ```

--------------------------------------------------------------------------------
- Method: DELETE /donation/delete-multiple
- Access: ADMIN, SUPER_ADMIN
- Headers: `Content-Type: application/json`
- Request Body:

  ```json
      "deletedCount": 2
  ```

```typescript
export type DONATION_PAYMENT_METHOD =
  | 'cash'
  | 'bank_transfer'
  | 'direct'
  | 'stripe'
  | 'other';

export type DONATION_TYPE = 'donation' | 'grant' | 'fund_raising';

export interface IDonation {
  _id: string;
  name: string;
  email: string;
  amount: number;
  transactionId?: string;
  type: DONATION_TYPE;
  payment_status: DONATION_PAYMENT_STATUS;
  payment_method?: DONATION_PAYMENT_METHOD;
  reference?: string;
  notes?: string;
  recordedBy?: {
    _id: string;
    name: string;
    email: string;
    role: string;
  };
  applicant?: {
    _id: string;
    projectTitle?: string;
    awardedAmount?: number;
    status?: string;
    quote?: string;
    successStory?: string;
    personal?: {
      firstName?: string;
      lastName?: string;
      email?: string;
      phone?: string;
    };
    applicationPeriod?: {
      _id: string;
      title?: string;
      startDate?: string;
      endDate?: string;
    };
  };
  createdAt: string;
  updatedAt: string;
}

export interface IFundStats {
  totalBalance: number;
  totalDonations: number;
  totalGrants: number;
  totalFundRaised: number; // Combines offline fundraising + paid store order revenues
  totalPaidExpenses: number; // Sum of paid operational expenses
  donationCount: number;
  grantCount: number;
  fundRaisedCount: number; // Combines offline fundraising entries + completed paid store orders
  paidExpenseCount: number; // Count of paid operational expenses
  totalCount: number;
  totalApplication: number;
}
```
