EXECUTIVE SUMMARY: ARCHITECTURE & SENIOR DEVELOPER ENHANCEMENTS
================================================================================
1. **Automated Platform Fund Synchronization**:
   - Marking an expense as `paid` automatically deducts the amount from `ProgramFund` balance.
   - Updating an expense's amount or toggling status (`paid` <-> `unpaid`/`cancelled`) automatically calculates the financial delta and adjusts `ProgramFund` in an atomic MongoDB transaction.
   - Deleting a single or batch of paid expenses automatically restores the funds into `ProgramFund`.
2. **Unified Financial Ledger (Transaction Sync)**:
   - Creating an expense automatically logs a financial `Transaction` with `category: 'Expense'`, `type: 'Debit'`, and matching status (`Success` or `Pending`).
   - Editing an expense updates the linked transaction record in lockstep.
3. **Automated Reference Generation**:
   - If no invoice or reference number is provided, the backend auto-generates a clean code chip (e.g., `EXP-XXXX`).
4. **Instant Aggregated Stats (`GET /expense/stats`)**:
   - Provides single-pass aggregated analytics: total volume, paid total, pending/unpaid total, cancelled total, category breakdown (`business`, `event`, `program`, `other`), and month-to-date metrics.
5. **Cross-Module Fund Integration**:
   - `GET /donation/fund-stats` includes `totalPaidExpenses` and `paidExpenseCount`, subtracting all paid operational expenses from the platform's `totalBalance`:
     `totalBalance = (totalDonations + totalFundRaised) - (totalGrants + totalPaidExpenses)`.
6. **Robust Route Hierarchy & Security**:
   - Protected with `auth(USER_ROLES.SUPER_ADMIN, USER_ROLES.ADMIN)`.
   - Explicit routes (`/stats`, `/delete-multiple`) prioritized ahead of parameterized routes (`/:id`) to prevent routing collisions.

1. GET EXPENSE STATISTICS

2. GET ALL EXPENSES (WITH PAGINATION, SEARCH & FILTERS)

  - `payment_status`: "paid" | "unpaid" | "cancelled"

  - `sort`: string (default: "-expenseDate")

3. GET SINGLE EXPENSE DETAILS
--------------------------------------------------------------------------------
- Method: `GET /expense/:id`
- Access: ADMIN, SUPER_ADMIN

--------------------------------------------------------------------------------
4. RECORD NEW EXPENSE
--------------------------------------------------------------------------------
- Method: `POST /expense`
- Access: ADMIN, SUPER_ADMIN
- Request Body:
  ```json
  {
    "title": "Venue Sound System Rental",
    "amount": 350.00,
    "category": "event",
    "subcategory": "rental",
    "payment_status": "paid",
    "payment_method": "cash",
    "expenseDate": "2026-10-02T00:00:00.000Z",
    "reference": "RENT-SND-09",
    "notes": "Paid cash to sound engineer for gala presentation."
  }
  ```
- Behavior:
  - Auto-assigns `recordedBy: admin.id`.
  - Auto-generates `reference` (`EXP-XXXX`) if not supplied.
  - If `payment_status: "paid"`, immediately deducts `$amount` from `ProgramFund`.
  - Creates a platform `Transaction` audit ledger entry.
- Response (201 Created):
  ```json
  {
    "statusCode": 201,
    "success": true,
    "message": "Expense recorded successfully",
    "data": {
      "_id": "67ee2b3c4d5e6f7a8b9c02",
      "title": "Venue Sound System Rental",
      "amount": 350.00,
      "category": "event",
      "subcategory": "rental",
      "payment_status": "paid",
      "payment_method": "cash",
      "expenseDate": "2026-10-02T00:00:00.000Z",
      "reference": "RENT-SND-09",
      "recordedBy": {
        "_id": "67cb1a...",
        "name": "Super Admin",
        "email": "admin@ifundayiti.org"
      }
    }
  }
  ```

--------------------------------------------------------------------------------
5. UPDATE EXPENSE (FULL EDIT)
--------------------------------------------------------------------------------
- Method: `PATCH /expense/:id`
- Access: ADMIN, SUPER_ADMIN
- Request Body (all fields optional):
  ```json
  {
    "title": "Venue Sound System Rental & Microphones",
    "amount": 400.00,
    "notes": "Added 2 wireless microphones to rental."
  }
  ```
- Behavior:
  - If amount or payment status changes, automatically recalculates and adjusts `ProgramFund` delta.
  - Synchronizes linked ledger `Transaction`.
- Response (200 OK): Returns updated expense object.

--------------------------------------------------------------------------------
6. QUICK STATUS TOGGLE
--------------------------------------------------------------------------------
- Method: `PATCH /expense/:id/status` (or `PATCH /expense/:id`)
- Access: ADMIN, SUPER_ADMIN
- Request Body:
  ```json
  {
    "payment_status": "paid"
  }
  ```
- Response (200 OK): Returns updated expense object.

--------------------------------------------------------------------------------
7. DELETE SINGLE EXPENSE
--------------------------------------------------------------------------------
- Method: `DELETE /expense/:id`
- Access: ADMIN, SUPER_ADMIN
- Behavior:
  - If the expense was marked `paid`, the `$amount` is automatically restored back to `ProgramFund`.
  - Removes linked transaction entry.
- Response (200 OK):
  ```json
  {
    "statusCode": 200,
    "success": true,
    "message": "Expense deleted successfully",
    "data": null
  }
  ```

--------------------------------------------------------------------------------
8. BATCH DELETE MULTIPLE EXPENSES
--------------------------------------------------------------------------------
- Method: `DELETE /expense/delete-multiple`
- Access: ADMIN, SUPER_ADMIN
- Request Body:
  ```json
  {
    "ids": ["67ee1a2b3c4d5e6f7a8b9c01", "67ee2b3c4d5e6f7a8b9c02"]
  }
  ```
- Behavior:
  - Calculates total paid amount among deleted items and restores it to `ProgramFund`.
- Response (200 OK):
  ```json
  {
    "statusCode": 200,
    "success": true,
    "message": "Expenses deleted successfully",
    "data": {
      "deletedCount": 2
    }
  }
  ```
